internal/auth verified route table — the frontend contract
=============================================================

Generated by actually probing a running test server (see the now-deleted
internal/auth/routedump_test.go — TestRouteDump — for the method used: every candidate route
below returned something other than 404 when hit with the listed method; a route not on this
list, or hit with a different method, 404s). Pinned Limen commit:
c6a34aa6dcb4d51a480e2c6ed9cb43e5c6f92ac4.

All routes are mounted under the base path /api/v1/auth (internal/auth.buildLimenConfig's
limen.WithHTTPBasePath). "protected" means the route 401s with no session cookie. Limen's CSRF
protection (on by default) additionally 403s any state-changing method (POST/PUT/PATCH/DELETE)
that lacks a valid CSRF token/header, checked before the auth check — so a POST/PUT/PATCH/DELETE
route below still requires a session even though probing it unauthenticated shows 403, not 401,
first.
