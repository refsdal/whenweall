# Contributing to whenweall

Thanks for your interest in contributing.

## Layout

The backend is Go (`cmd/whenweall`, `internal/*`); the frontend is a standalone SPA under
`web/` (React 19, TanStack Router, Vite, bun). See the [Development](./README.md#development)
section of the README for how to run both locally, and
[Project structure](./README.md#project-structure) for what lives where.

## Development approach

This project is developed test-driven: write a failing test first, then the code that makes
it pass. New behaviour should land with tests, not after.

## Database changes

Schema changes are [goose](https://github.com/pressly/goose) SQL migrations under
`migrations/`, applied on boot (or via `go run ./cmd/whenweall migrate`) and by the test
suite's own `testcontainers-go` harness. Add a new numbered file; never edit a migration
that has already shipped.

Queries against that schema are generated by [sqlc](https://sqlc.dev/) (`sqlc.yaml`) from
`.sql` files in `internal/polls/queries` and `internal/bookings/queries` — write the query
there, then run `sqlc generate` from the repo root to regenerate the typed Go it produces
into the same directory. Don't hand-edit generated query code.

`internal/auth`'s own schema (`migrations/00002_auth.sql`) is a special case: it's Limen's
generated schema, hand-folded into a goose migration once, plus our own `staff_users` table
appended at the end. Regenerating it (needed after a Limen upgrade, or a new plugin) has its
own steps — see [`docs/limen-migrations.md`](./docs/limen-migrations.md).

## Commit messages

Commits follow [Conventional Commits](https://www.conventionalcommits.org/)
(`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, ...).

## Before opening a pull request

Run the same checks CI runs, and make sure they pass:

```bash
go test ./... && go vet ./... && golangci-lint run ./...
cd web && bun run typecheck && bun run lint && bunx vitest run
```

End-to-end tests need a browser once per machine, then run against the real built SPA
served by the real Go binary (see [`e2e/run-server.sh`](./e2e/run-server.sh)):

```bash
bunx playwright install --with-deps chromium
bunx playwright test
```

If your change touches the realtime WebSocket protocol (`internal/rooms`), read and update
[`internal/rooms/PROTOCOL.md`](./internal/rooms/PROTOCOL.md) — it's the wire contract both
the Go hub and `web/src/lib/room-socket.ts` are held to.

If your change alters the UI in a way the README screenshots show, regenerate them with
`bun run screenshots` and include the updated PNGs — see
[docs/screenshots/README.md](./docs/screenshots/README.md).

Then open a PR using the provided template, describing the change and how you tested it.
